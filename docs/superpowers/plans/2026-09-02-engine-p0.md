# Engine P0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add many-to-one joins with dual-grant enforcement, versioned reversible schema changes, a grant-filtered history API, and an admin audit query API to `KitsuneEngine`.

**Architecture:** Extend the existing query compiler so one INNER JOIN follows a relation FK on the root collection. Both collections' field masks and row predicates are injected as parameterized SQL. Schema changes are owner-role DDL recorded in `kitsune.schema_revisions` with warn-then-confirm stale change sets. History and audit are new engine methods that reuse grant resolution; they do not talk to Postgres except through the compiler/session path (history reads `__rev` after a live-row grant check).

**Tech Stack:** TypeScript, Postgres 16, Vitest acceptance suite, MCP tool schemas.

## Global Constraints

- No `SELECT *`. Explicit column lists from field masks.
- Authorization proven against `packages/acceptance/src/oracle.ts`, not the compiler.
- Agents remain capped at `propose` unless audited admin override.
- Row predicates are JSON compiled to parameterized SQL.
- `kitsune_app` has no `BYPASSRLS`; DDL runs as `kitsune_owner`.
- Join is many-to-one only; inverse one-to-many is out of this plan.
- Schema ops: `addField`, `dropField`, `setIndexed` only. No retype or rename.
